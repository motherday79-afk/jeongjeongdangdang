# 정참시 v2.2.19 · 사이드바 NOW ISSUE 복구 + 방문자 일마감

## 1. 메인 오른쪽 사이드 순서 고정

메인 오른쪽 사이드는 아래 순서를 유지합니다.

1. NOW ISSUE
2. 정참시 자체 설문조사
3. 실시간 급상승 TOP10
4. 정참시News

v2.2.17~18에서 저장된 NOW ISSUE 설정이 `enabled=false`인 경우 카드가 사라질 수 있어, v2.2.19 첫 설정 로드시 1회에 한해 NOW ISSUE를 ON으로 복구합니다. 이후 어드민에서 저장한 ON/OFF는 그대로 유지됩니다.

## 2. 방문자 누적을 '전일까지 확정 + 오늘' 구조로 변경

이전 버전의 누적 방문은 Redis 전체 고유 브라우저 HLL과 어드민 보정값을 직접 합산했습니다. 그래서 어드민에서 보정값을 초기화하면 과거에 표시하던 누적값이 갑자기 작아질 수 있었습니다.

v2.2.19부터는 다음처럼 동작합니다.

- `fixedTotal`: 전일까지 확정된 누적 방문
- `today`: 오늘 KST 00:00 이후의 고유 브라우저 방문 + 오늘 보정
- `total`: `fixedTotal + today + 현재일 누적 추가 보정`

예: 전날 누적이 500으로 끝났다면 다음 날 첫 방문 시 TODAY 1, 누적 501이 됩니다.

## 3. KST 자정 일마감

- Vercel Cron: 매일 `15:00 UTC` (`00:00 KST`)에 `/api/cron/finalize-visitors` 호출
- 전날 최종 TODAY/누적 값을 날짜별 확정 데이터로 저장
- 새 날짜는 TODAY 보정을 0으로 초기화
- 전날 최종 누적을 새 날짜의 `fixedTotal`로 이월
- Cron이 지연/누락돼도 첫 방문·통계 조회·어드민 조회 시 날짜 변경을 감지해 동일한 일마감을 자동 수행

Vercel 프로젝트에 `CRON_SECRET`이 설정되어 있으면 Cron 요청의 Authorization 헤더를 검증합니다. 설정하지 않아도 일마감 API는 날짜가 실제 변경된 경우에만 멱등적으로 이월합니다.

## 4. 어드민 방문자 초기화 의미 변경

`실제 집계값으로 초기화`를 `오늘 보정값 초기화`로 변경했습니다.

초기화 시:

- 전일까지 확정 누적은 유지
- 오늘 TODAY 보정만 0
- 오늘 누적 추가 보정만 0
- 실제 오늘 방문은 유지

따라서 전일까지 확정된 누적이 다시 1, 3 같은 원시 HLL 숫자로 떨어지지 않습니다.

## 5. 기존 데이터 마이그레이션

기존 v1 방문자 표시 설정이 있으면 현재 화면에 보이던 TODAY/누적을 그대로 유지하도록 v2 상태로 1회 변환합니다. 이후부터 새 일마감 규칙을 사용합니다.
